# Инструменты разработки AGR Collision

Не входят в аддон. Всё запускается либо системным Python (есть numpy, scipy, PIL),
либо фоновым Blender:

    BL="C:/Program Files (x86)/Steam/steamapps/common/Blender/blender.exe"
    "$BL" -b --factory-startup --python-exit-code 1 --python <script>.py -- <args>

`WT` ниже — корень рабочей копии аддона (папка, внутри которой лежит
`xivgate_agr_collision`).

## Связь с открытым Blender

`bl.py` — клиент к аддону «MCP for Blender», который слушает 127.0.0.1:45876.
Инструменты MCP этой сессии не подходят: мост ждёт другой аддон и другой
протокол (он шлёт ответ без перевода строки). Использование:

    echo 'import bpy; print(len(bpy.data.objects))' | python bl.py
    python bl.py script.py          # выполнить файл в открытом Blender

## Тестовые меши

* `cube.npz` — башня из сцены пользователя (`Cube`), 1 050 вершин, 2 096 треугольников,
  замкнута, 0 неманифолдных рёбер. Ключи: `v`, `f` (мировые координаты, float64).
* `house.npz` — синтетический дом: полые стены 25 см, дверь, два окна, арка,
  ниша 12 см. Строится заново скриптом `house.py`.

## Прогон и замеры

* `dumpall2.py -- WT mesh.npz PREFIX [PASSES]` — декомпозиция (PASSES — значение
  Optimization Passes, по умолчанию 1); пишет `PREFIX_hulls.npz`,
  `PREFIX_thin.npz`, `PREFIX_invalid.npz`, печатает время, число хуллов,
  треугольники и предупреждения.
* `summary.py hulls.npz` — число хуллов и треугольников, распределение толщин,
  количество «полос» (длиннее 10 м и тоньше 20 см).
* `eval2.py mesh.npz hulls.npz --n 300000` — объёмные метрики через qhull и
  число оборотов: лишний объём вне исходника, недокрытие, пересечения.
* `verify2.py mesh.npz hulls.npz [probe]` — точечная проверка: точки на гранях
  хуллов, смещённые внутрь по нормали, и точное расстояние до поверхности
  исходника. Показывает настоящий выход за модель.
* `overlaps.py -- WT hulls.npz` — пересечения пар хуллов с глубиной, вершины
  округляются до float32, как при экспорте.
* `plan.py mesh.npz hulls.npz Z CX CY HALF out.png` — сечение в плане:
  контур исходника белым, контуры хуллов цветом. Лучший инструмент для
  разбора «почему здесь столько кусков».
* `render.py -- hulls.npz OUT hulls|source [extra.npz]` — три ракурса в
  Workbench, каждый хулл своим цветом. `render_zoom.py` — крупный план.
* `prof.py -- WT mesh.npz out.prof` — cProfile прогона.

## Разбор причин

* `mergewhy.py -- WT mesh.npz` — по каждой паре соседей, у которых объединение
  почти выпуклое, печатает причину отказа склеивания.
* `pairwhy.py -- WT mesh.npz "x,y,z"` — трасса разрезов вокруг точки и
  подробности отказов для конкретных пар.
* `fallbackstat.py -- WT mesh.npz` — сколько разрезов сделано плоскостями
  граней, сколько запасными плоскостями, сколько отклонено.
* `absorbcheck.py -- WT mesh.npz` — аудит поглощений оболочкой плотной
  проверкой по числу оборотов.

## Перебор вариантов и производительность

* `searchlog.py -- WT mesh.npz [PASSES]` — журнал каждого варианта перебора:
  размер и глубина узла, skip, время, выигрыш; сводки по глубине, skip и
  кумулятивная кривая «время → выигрыш».
* `budget.py -- WT mesh.npz` — итоговые хуллы, треугольники и время при разных
  бюджетах перебора.
* `lookahead.py -- WT mesh.npz` — качество и время при урезанном переборе резов
  (`CUT_LOOKAHEAD` / `MAX_CUT_ATTEMPTS`).
* `reflex.py -- WT mesh.npz` — число вогнутых рёбер по порогам глубины.
* `cellstat.py -- WT parts.npz` — популяция частей: где объём, тонкие и
  вытянутые куски.

## Отладчик коллизии

* `hull64check.py WT hulls.npz` — системным Python со scipy сверяет
  `core/hull64.py` с qhull: случайные облака, копланарная сетка и все хуллы
  набора в float64 и после округления до float32 (как их хранит Blender).
* `inspectcheck.py -- WT hulls.npz` — фоновым Blender: ложные срабатывания
  отладчика на реальных хуллах и синтетические дефекты (вмятина 0,1 и 0,01 мм,
  Г-образный блок, мелкий кубик, тонкая пластина, 128-гранный цилиндр).

## Что проверено (башня, 2 096 треугольников, допуск 2 см)

Подходы, которые **не** улучшили результат 1.3.0 (287 хуллов), — чтобы не
проверять их заново:

| подход | результат |
|---|---|
| резы только глобальными «несущими» плоскостями модели | 4 125 ячеек, 546 с |
| снаппинг локальных плоскостей резов на глобальные | 497 ячеек, тонких 135 |
| метрика вогнутости CoACD `max(H_b, k·R_v)` в жадном выборе реза | 336 |
| урезанный перебор резов (lookahead 1–8) | 301–448, и не быстрее |
| сборка снизу вверх: только точно выпуклые слияния | 335 |
| сборка снизу вверх: рост от крупных объёмов (стоимость Knodt & Gao 2026) | 297 |
| запрет резов, оставляющих вытянутые пластины | 284 из 297 |
| UCB-выбор узла в переборе | 273 при 297 вариантах |
| приоритет перебора «куски на единицу работы поддерева» | 248 только при полном исчерпании |
| перебор без корня и крупных поддеревьев | 266 при 297 вариантах |

Почему потолок близко: у башни 689 вогнутых рёбер глубже 2 см, и 287 хуллов —
это уже 0,42 от их числа (худший случай для многогранника — порядка r²).

Что сработало (вошло в 1.3.1): кэш ранжирования и резов на куске, пропуск
вариантов с уже проверенным верхним резом, узел не списывается после трёх
попыток, а идёт вниз по своим плоскостям; крупным поддеревьям (более четверти
работы всей модели) — одна попытка. Optimization Passes = 100: 259 хуллов,
5 382 треугольника за ~6,6 мин против 267 / 5 774 за ~11 мин у 1.3.0.
